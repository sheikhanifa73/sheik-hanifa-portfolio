PERSONAL PROJECT / ENGINEERING WALKTHROUGH

MaterialFlow

A practical materials-ordering demo connecting mobile clients, a web app and a shared API. Built with AI assistance; intended for explanation, experimentation and further independent development.

Current implementation runs locally. Cloud hosting, device validation and app-store releases are not yet complete.

The user journey

  1. Customer signs in and sees available products, AED prices and stock.
  2. Customer selects quantities and places an order. The server checks stock and computes the total.
  3. Repeated checkout requests reuse an idempotency key, preventing duplicate orders.
  4. Operator signs in, reviews orders and advances the status through confirmation, dispatch and delivery.
  5. Customer refreshes order status through periodic polling. A timeline explains the changes.

The implemented architecture

SwiftUI · Flutter · React Native · React web ↓ JSON / REST Node.js HTTP API ↓ transactions SQLite Customer: own orders only Operator: fulfilment transitions API: authoritative prices, stock and role checks

Why these choices?

One API makes business rules consistent across interfaces. SQLite keeps the local demo easy to run. Transactions prevent partial stock updates. Idempotency makes a retry safe after an uncertain network result. Version checks prevent one operator from overwriting another operator’s newer decision.

Cloud direction

Vercel will serve the portfolio and web assets. Supabase is the intended hosted PostgreSQL and authentication provider. Migrating requires replacing the local session and database layer, implementing row-level security, and testing transactional order functions against the hosted backend. A static deployment alone does not migrate the API.

What to demonstrate in an interview

  1. Place an order and explain the request and response.
  2. Retry it with the same key, then explain the changed-payload conflict.
  3. Show that a second customer cannot read the first customer's order.
  4. Move an order through its fulfilment stages as an operator.
  5. Explain failure states, token expiry, cancellation and stock restoration.
  6. Describe remaining production work: real authentication, secure token storage, auditing, backups, rate limits and observability.
